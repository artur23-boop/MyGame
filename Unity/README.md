# Царь горы — Unity 3D

Отдельная реализация GDD для Unity **6000.6.6f1**, C#, URP **17.6.0**, Windows x64 и macOS. Браузерная версия в корне репозитория независима от этого проекта.

## Запуск по шагам

1. Установите **Unity Hub** с официального сайта Unity. Войдите в аккаунт и активируйте подходящую лицензию (например, Personal, если вы соответствуете её условиям).
2. Установите редактор **Unity 6.6 (6000.6.6f1)**. На MacBook с M1/M2/M3/M4/M5 выбирайте **Apple silicon**, на MacBook с Intel — **Intel**. Для запуска в редакторе дополнительные платформенные модули не нужны; для сборки exe добавьте **Windows Build Support (Mono)**. Перед переходом с Unity 2022 закройте редактор, сохраните копию своих изменений и выберите новую версию проекта в Unity Hub. Старые сборки потребуется пересобрать.
3. Скачайте репозиторий с GitHub: **Code → Download ZIP**, распакуйте архив.
4. В Unity Hub нажмите **Add → Add project from disk**. Выберите именно папку **MyGame-main/Unity**, где лежат `Assets`, `Packages`, `ProjectSettings`.
5. Откройте проект. Дождитесь установки URP и окончания импорта/компиляции. Для первоначальной установки пакетов требуется Интернет.
6. Подготовка проекта выполнится автоматически. Если сцена не открылась, выберите **Winter Yard → Prepare project**. Затем откройте `Assets/KingOfTheHill/Scenes/WinterYard.unity`.
7. Нажмите **Play** сверху редактора, перейдите во вкладку **Game**, нажмите **«ВЫЙТИ ВО ДВОР»**. Для полноэкранного вида Game можно использовать Maximize On Play.

Двор создаётся при запуске сцены. Пустой вид сцены до нажатия Play — ожидаемое поведение. Скрипт подготовки создаёт URP-ресурсы в `Assets/KingOfTheHill/Rendering`, назначает рендеринг и включает стартовую сцену в сборку. Он сохраняет существующий рендеринг, если вы уже назначили свой.

## Управление

- **WASD** — движение относительно камеры; **мышь** — обзор и направление атаки.
- **Space** — прыжок, **Shift** — рывок с перезарядкой 3 с.
- **ЛКМ** — толчок перед собой, перезарядка 0,8 с.
- **ПКМ** — бросить снежок по дуге. После броска он автоматически перезаряжается за **2,5 с**; таймер виден в HUD.
- **Q** — суперснежок после комбо: 3 успешных попадания толчками или обычными снежками, не более 6 секунд между попаданиями. Промах или полученный удар сбрасывает незавершённую серию. Готовый суперснежок сохраняется до использования и делит перезарядку с обычным. Он золотистый, крупнее обычного, сбивает соперника и оставляет лежать **5 секунд**. Во время лежания нельзя двигаться, атаковать и получать очки; повторные удары не продлевают лежание и не дают комбо. Боты используют те же правила.
- **Esc** — пауза и освобождение курсора. Потеря фокуса во время матча тоже ставит игру на паузу.

## Что реализовано

Объёмный двор с четырьмя домами, тёплыми окнами и фонарями, лавочками, снеговиком и снегопадом. Физическая гора с ледяной площадкой, игрок и три бота, камера от третьего лица с проверкой препятствий, физическое отбрасывание, оглушение, прыжок, рывок, перезарядка снежков и суперснежок за комбо. Удержание вершины приносит 1 очко в секунду; в воздухе и при оглушении очки не идут. Очки после падения сохраняются. Цель — 20/30/60 очков, меню сложности, громкость и чувствительность, пауза, результаты и повторный матч. Победы хранятся через PlayerPrefs, звуки синтезируются без сторонних ассетов.

## Сборка Windows

Выберите **Winter Yard → Build Windows x64**. Результат при успешной сборке: `Builds/Windows/KingOfTheHill.exe`. Для передачи игры архивируйте **всю** папку `Builds/Windows`, включая папку данных и DLL, а не только exe.

Альтернатива — **File → Build Profiles → Windows → Switch Profile**, затем **Build**. Дождитесь окончания переключения профиля и импорта.

Автоматизированная сборка на машине с установленным и лицензированным редактором и модулем Windows:

```text
Unity -batchmode -quit -projectPath "<путь к MyGame/Unity>" -executeMethod WinterYardEditor.ProjectSetup.BuildWindows -logFile "<путь к build.log>"
```

На Windows используйте полный путь к `Unity.exe`. Не запускайте второй экземпляр редактора на уже открытом проекте. `WINTER_YARD_BUILD_PATH` может задавать другой путь вывода с именем exe.

## Сборка приложения для MacBook

На Mac выберите **Winter Yard → Build macOS (Universal)**. При успешной сборке получится `Builds/macOS/KingOfTheHill.app` для Intel и Apple silicon. Для другой папки задайте `WINTER_YARD_MAC_BUILD_PATH` (путь должен оканчиваться на `.app`). Скрипт временно выбирает Universal и восстанавливает прежнюю настройку после сборки.

Альтернатива: **File → Build Profiles → macOS → Switch Profile**, выберите архитектуру **Intel 64-bit + Apple silicon**, затем **Build**. Модуль macOS должен быть доступен для установленного редактора. Для распространения за пределами собственного компьютера подпись и notarization настраиваются отдельно; этот проект их не выполняет.

## Переход с Unity 2022

Скачайте актуальный архив целиком: изменились не только `ProjectVersion.txt`, но и URP, скрипты физики и инструменты сборки. В Hub выбирайте папку `Unity`. Не копируйте старые `Library`, `Temp`, `Obj` и `UserSettings` в новую копию. Если уже создавали собственные сцены/ассеты, сохраните их отдельно перед обновлением.

В Unity 6 используются `Rigidbody.linearVelocity`, `linearDamping`, `angularDamping`, `PhysicsMaterial` и актуальный поиск объектов. Проект использует **Input Manager (Old)**; команда подготовки назначает эту настройку. Если Console просит перезапустить редактор после изменения Active Input Handling, перезапустите его перед Play или Build. Отдельную зависимость `com.unity.modules.inputlegacy` добавлять не нужно: этот идентификатор не разрешается Package Manager.

Версия **6000.6.6f1** выбрана как наибольший финальный тег в [официальном репозитории UnityCsReference](https://github.com/Unity-Technologies/UnityCsReference/tree/6000.6.6f1). Alpha/Beta исключены. Основной архив релизов и реестр пакетов Unity из облачной среды недоступны; доступность редактора в Hub и разрешение URP **17.6.0** нужно подтвердить при импорте. Версия URP сверена с [`package.json` официального репозитория Unity-Technologies/Graphics](https://github.com/Unity-Technologies/Graphics/blob/a7e4c051d256a781ab362c64316b125a1e104694/Packages/com.unity.render-pipelines.universal/package.json). Это не утверждение, что данный релиз имеет статус LTS.

## Статус проверки и ограничения

В облачной среде Unity Editor и лицензия отсутствуют: **проект не компилировался и не запускался в Unity, сборки Windows/macOS не выполнены**. Выполнена статическая проверка структуры и синтаксиса C#; она не подтверждает совместимость Unity API, качество физики и поведение игры. Первую полноценную проверку нужно выполнить по шагам выше; при ошибках пришлите красные сообщения из Console.

Это исходная 3D-итерация: персонажи собраны из примитивов, суставной ragdoll реализован в CharacterRig; его физика требует проверки в Play Mode. Нет анимационных клипов, голосовых реплик, мультиплеера или мобильного управления. Сложность меняет частоту принятия решений ботов. Точный баланс и длительность матча требуют проверки в редакторе.


## Если Package Manager сообщает, что Inputlegacy не найден

Закройте Unity. В локальном проекте замените `Packages/manifest.json` файлом из актуального репозитория и снова откройте проект. Исправление удаляет ошибочную зависимость `com.unity.modules.inputlegacy`; удалять папку Assets или создавать новый проект не требуется. Также можно удалить пакет через Package Manager → Inputlegacy → Manage → Remove, если этот пункт доступен. После импорта проверьте Console. Это устраняет конкретную ошибку зависимости, показанную на скриншоте; полная компиляция и запуск по-прежнему требуют проверки в редакторе.


## Проверки боевой системы

Меню **Winter Yard → Run combat rules checks** проверяет чистые правила перезарядки, комбо, расхода суперснежка и пятисекундного лежания. Проверки завершаются сообщением в Console или исключением при нарушении правил. В облаке они не выполнялись, поскольку Unity отсутствует. Они не заменяют проверку попаданий и падения в Play Mode: сделайте три успешных попадания, дождитесь перезарядки, нажмите Q и убедитесь, что цель лежит пять секунд и затем возвращается к управлению. Пауза должна замораживать все таймеры. Сильные попадания теперь включают суставной ragdoll (см. обновление ниже).


## Вязкий снег

Двор покрыт отдельной сеткой снега с MeshCollider: четыре светло-синие утоптанные дорожки имеют глубину около 4,5 см, рыхлый снег вне дорожек — до 50 см. Высота поверхности и характеристики движения вычисляются одной функцией `SnowSurface.Sample`, переходы плавные. На снегу скорость составляет примерно 2,65–4,8 м/с; рыхлый снег замедляет разгон, быстрее гасит движение, сокращает рывок и немного снижает прыжок. На склоне скорость 4,4 м/с, на вершине — лёд с малым сопротивлением и более долгим торможением. Правила одинаковы для игрока и ботов; соперников по-прежнему можно отбрасывать.

Ноги визуально погружаются, шаги сопровождаются подъёмом ботинок и небольшим покачиванием корпуса. На снегу остаются следы на 12 секунд и частицы из-под ног; на льду следов нет. Следы используют пул из 240 объектов, частицы ограничены 160 одновременно, при повторном матче следы очищаются. В HUD видны поверхность и глубина. Шаги теперь уплотняют поле глубины и обновляют сетку/коллайдеры затронутых участков (см. обновление ниже).

Для проверки выберите **Winter Yard → Run snow surface checks**. Затем в Play сравните движение, остановку, прыжок и рывок на дорожке, в рыхлом снегу и на вершине; проверьте следы на склоне, паузу, повторный матч и отбрасывание снежком. Проверки Unity и визуальная оценка в облаке не выполнялись: редактор отсутствует. Числа требуют проверки баланса на реальном запуске.

## Прицел снежков и толчок

Перед персонажем отображается баллистическая дуга и кольцо предполагаемого попадания. Направление задаётся поворотом камеры мышью; угол броска пока фиксирован. Серая дуга означает перезарядку, голубая — обычный снежок, золотая — доступный суперснежок Q. При готовом суперснежке показана его траектория с увеличенным радиусом; ПКМ по-прежнему бросает обычный снежок. Прогноз учитывает гравитацию, размер снаряда, землю, стены и текущие позиции соперников, но не предсказывает движение ботов. Начальная позиция, скорость и радиус берутся из тех же функций, что используются при броске.

Возвращены прежние параметры толчка: горизонтальная сила 8, вертикальная составляющая 2, дополнительное ускорение оглушённого персонажа наружу горы 6. На льду и склоне соперник всё ещё может проскользить дальше, чем в снегу. Оглушение обычным толчком и правила комбо сохранены.

Проверка в Play: поверните камеру в сторону бота/стены/снега, сравните дугу с попаданием обычного и суперснежка, проверьте серый цвет при перезарядке, скрытие дуги при паузе, а затем толчки на рыхлом снегу и на вершине. Проверка в редакторе в облачной среде не выполнялась.


## Возврат в меню и закрытие игры

В паузе (Esc) и на экране результатов кнопка **ВЫХОД В ГЛАВНОЕ МЕНЮ** возвращает главное меню: сбрасывает текущий матч, очищает снежки и следы, освобождает курсор и восстанавливает масштаб времени. Настройки сложности, цели, громкости и чувствительности сохраняются до закрытия приложения. В самом главном меню отдельная кнопка **ЗАКРЫТЬ ИГРУ** завершает приложение; в редакторе она останавливает Play Mode. Проверка: Esc → выход в меню → новый матч, а также результаты → выход в меню → новый матч. Поведение UI в Unity в облаке не проверено.


## Приветственный экран — главное меню

При запуске показывается приветственный экран «ЦАРЬ ГОРЫ»: **ИГРАТЬ — ВЫЙТИ ВО ДВОР**, **НАСТРОЙКИ**, **ЗАКРЫТЬ ИГРУ**, счётчик побед и управление. На фоне — общий вид зимнего двора. Настройки открываются отдельным экраном; кнопка «Назад в главное меню» и Esc возвращают на приветствие.

Во время матча нажмите Esc и **ВЫХОД В ГЛАВНОЕ МЕНЮ** — откроется именно приветственный экран. Такая же кнопка есть после результатов. Текущий матч сбрасывается, новый начинается только после нажатия «Играть». Esc во время стартового отсчёта тоже возвращает на приветствие. «Закрыть игру» завершает приложение (в редакторе останавливает Play Mode).

Проверка в Unity: запуск → приветствие → настройки → назад → играть → Esc → выход → приветствие → новый матч; отдельно результаты → выход → приветствие. Проверка UI в облаке не выполнялась.

## Rigidbody и AddForce

Персонажи имеют динамический Rigidbody и CapsuleCollider. Движение выполняется в FixedUpdate через `AddForce(..., ForceMode.Force)`, прыжок, рывок и отбрасывание — через `ForceMode.Impulse`. Масса теперь влияет на ускорение от силы и изменение скорости от импульса: тяжёлого персонажа труднее столкнуть, но он медленнее разгоняется и ниже прыгает при прежних настройках. При массе 1 сохранены прежние величины толчка (8 по горизонтали и 2 вверх). Снежки также имеют Rigidbody, гравитацию и непрерывное обнаружение столкновений.

В Play Mode выберите персонажа в Hierarchy → Fighter → **Rigidbody physics**: Body Mass, Movement Force Scale, Jump Impulse Scale, Dash Impulse Scale, Push Impulse, Push Up Impulse. Эти персонажи создаются при запуске: изменения Inspector во время Play предназначены для настройки и не сохраняются после остановки/нового матча. Массу можно изменять и прямо в Rigidbody. В обычном движении вращение капсулы ограничено; при сильном попадании управление передаётся суставным физическим частям, капсула временно отключается.

Проверьте ходьбу на снегу и льду, прыжок, рывок, толчок и удар снежком при массе 1 и 2. Проверка синтаксиса в облаке не заменяет запуск PhysX в Unity; физический баланс здесь не проверен.


## Обновление: суставной ragdoll, анимации и протаптывание

**CharacterRig** создаёт 11 физических частей и 10 CharacterJoint: таз, корпус, голова, сегменты рук и ног. При обычном движении их тела кинематические, а ходьба/бег, движение рук, прыжок, толчок, бросок и подъём анимируются процедурно. Это не импортированные Humanoid/Mixamo-клипы. При попадании в голову и суперснежке части становятся динамическими, основная капсула отключается; камера следует за тазом. Самостолкновения частей отключены, повороты суставов ограничены. Во время ragdoll действия и очки заблокированы, повторные удары не дают комбо. Суперснежок удерживает состояние не менее 5 секунд; затем персонаж ищет опору и свободное место для подъёма, после чего действует короткое восстановление 0,45 с. В воздухе или у препятствия подъём может занять больше пяти секунд.

**Протаптывание**: каждый шаг в снегу вне горы уменьшает глубину вокруг ноги в радиусе 0,7 м, максимум на 4,5 см в центре за шаг. Повторные проходы постепенно уплотняют тропу, оставляя минимум 4,5 см снега; скорость движения растёт, сопротивление уменьшается. Меняются и вершины сетки, и MeshCollider. Поле разделено на 16 участков по 800 треугольников; только затронутые участки обновляются не чаще одного раза за 0,2 с. Физическая поверхность может отставать от нового поля глубины до следующего обновления. Следы следуют за проседающей поверхностью. Уплотнение сохраняется до следующего матча; ледяная вершина и склон не деформируются. При повторном раунде/выходе в меню снег восстанавливается.

Проверки: **Winter Yard → Run snow surface checks** проверяет уплотнение, изменение скорости и сброс карты, сохраняя существующие тропы после проверки. **Winter Yard → Run ragdoll structure checks (Play Mode)** проверяет число тел/суставов, переход к физике и защиту лежащей цели. Далее вручную проверьте: голову/суперснежок → падение → пять секунд → подъём на ровной площадке и склоне; ходьбу и атаки всех персонажей; повторные проходы по рыхлому снегу → видимая тропа → новый матч → свежий снег. Проверяйте паузу и выход в меню во время падения. В облаке выполнена проверка синтаксиса, но Unity Editor отсутствует: физика суставов, подъём и производительность пересчёта коллайдеров не проверены запуском.
